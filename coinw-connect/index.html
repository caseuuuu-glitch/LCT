01. 项目概述

一句话：CoinW Connect 是 CoinW 自有品牌的法币买卖入口。用户在 CoinW 内选择币种、法币与支付方式，后台路由至合适 PSP / On-ramp Provider，尽量保持原生 UI、复用 KYC，并由 CoinW 统一展示报价、订单与售后。

核心问题：第三方跳转、重复 KYC、报价不可比、支付方式分散、品牌割裂。产品原则：CoinW First、Payment Method First、Native before Redirect、One Router。

02. 目标与指标

目标建议指标
提升买币转化Visit → Buy Now +10%~20%

降低单通道依赖关键市场 ≥2 可用通道
SEO 获客Asset×Fiat Landing Pages

North Star：Completed Buy/Sell Orders / Qualified Buy Page Visitors。

首期不做：P2P、复杂 OTC、自建全球 acquiring。

07. 核心规则

  • 只展示 enabled 的 Asset×Fiat×Country 组合。
  • 金额需同时满足 CoinW、Provider、支付方式、KYC Tier 限额。
  • Recommended 排序建议：可用性 > 摩擦 > 成功率 > 成本 > ETA。
  • 配置页价格为 estimate；执行前 Quote 必须含 quote_id、expires_at、effective_price、fee、receive_amount。
  • Quote 过期自动刷新；变化超过阈值需二次确认。

08. CoinW Connect 架构

定义：CoinW Connect = CoinW 自有 Payment/On-ramp Experience Layer + Routing Layer，不等于单一 PSP。
层职责
CoinW UX支付方式、认证、报价、订单、客服。
RouterEligibility、Provider 选择、Quote 聚合、Fallback、成本/成功率策略。
ConnectorPSP / On-ramp API、SDK、KYC Reliance、Webhook、Settlement。
LedgerUID/订单关联、资产入账、对账、补单。

Provider 最低要求：优先 Full API / Headless / Embedded SDK；Quote/Order/Status/Webhook；Card 支持 3DS/Tokenization；优先 KYC Reliance。候选包括 Banxa Native、OSL Pay OpenAPI、Transak Whitelabel、Nuvei、Checkout.com + Crypto Provider 等，最终以商务/牌照/覆盖为准。

09. 登录 / KYC

状态动作
未登录Sign up / Log in；Email/Phone、Google、Apple、Telegram。

KYC Processing禁止支付。
KYC Passed请求 Eligibility / Quote。

10. 支付方式与报价

  • Debit/Credit Card：Visa、Mastercard。
  • Apple Pay / Google Pay：独立一行，按设备/地区/Provider 可用性展示。
  • Bank Transfer：P1；按地区配置 local rail。
  • Third Party：原生能力不可用或显著更优时 fallback。

认证后 Quote 卡建议只保留 Provider、Receive、Effective Price、Fee、ETA、Best，避免重复信息。

12. 异常场景

  • Quote 过期：刷新并必要时二次确认。
  • Provider 不可用：Router 尝试下一通道。
  • 3DS 失败：保留订单，可 Retry 或换方式。
  • 支付成功未到账：进入 CRYPTO_PROCESSING，禁止重复扣款。
  • 切换 fiat/asset：旧 Quote 立即失效。
  • 地区受限：隐藏不可用方式；全不可用给替代路径。

13. 风控与合规

  • Eligibility 结合账户实体、居住国、IP、KYC Level、支付工具国家。
  • Card：3DS、CVV/AVS（适用时）、velocity、device/fraud signals。
  • 制裁/PEP/高风险地区沿用 CoinW 账户层规则。
  • 支付工具持有人与 KYC 姓名不一致策略需合规确认。
  • Provider decision、Webhook、人工操作完整 Audit Log。

17. 后台 / 运营

  • Country → Fiat → Asset → Payment Method → Provider 配置。
  • Provider 开关、优先级、成本、限额、Maintenance、Fallback。
  • Recommended 规则权重。
  • 订单搜索、失败原因、Refresh Status、Retry Webhook、Export。
  • SEO/FAQ/How to Buy 内容可配置。

18. 多语言与本地化

  • Asset Symbol / Fiat code 固定英文，描述本地化。
  • 金额与小数精度按 locale 处理。
  • Supported Payment Methods 按地区动态。
  • SEO 使用 hreflang + 本地法币关键词。
  • 移动端 Supported 单行横滑，不换两行。

19. 验收标准

  1. USD→EUR 后 H1、币种、estimate、Quote 同步。
  2. USDT→BTC 后 H1、Receive、Popular 高亮、Quote 同步。
  3. 未登录 Buy Now 必拉起注册/登录并恢复上下文。
  4. Apple Pay / Google Pay 独立；Card 仅 Visa/Mastercard。
  5. Recommended 只允许一个并与 Router 一致。
  6. 过期 Quote 不可提交。
  7. 重复点击不得重复建单/扣款。
  8. Desktop/Mobile 完整走通。
  9. Popular 5 个资产只用一次批量行情请求。
  10. SEO 内容未登录可抓取。
