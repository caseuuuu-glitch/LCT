01. 项目概述

一句话：CoinW Connect 是 CoinW 自有品牌的法币买卖入口。用户在 CoinW 内选择币种、法币与支付方式，CoinW 在后台路由至合适 PSP / On-ramp Provider，尽可能保持原生 UI、复用 KYC，并由 CoinW 统一展示报价、订单状态与售后入口。

背景

当前买币能力依赖不同第三方通道，用户可能面临跳转、二次 KYC、支付方式分散、报价不可比较、品牌割裂等问题。新方案希望把“Vendor 能力”包装成“CoinW Connect 能力”，让支付方式而不是 Provider 成为用户第一认知。

核心原则

  • CoinW First：用户看到的是 CoinW 的页面、价格、订单与客服入口。
  • Payment Method First：优先展示 Card / Apple Pay / Google Pay / Bank Transfer 等支付方式，Provider 退到底层。
  • Native before Redirect：优先原生 API / SDK / KYC Reliance；无法原生时再使用跳转型通道。
  • One Router：前台一套流程，后台按国家、法币、成本、成功率、KYC 摩擦、限额、可用性路由。

07. 核心业务规则

资产与法币

  • 前端只展示后端配置为 enabled 的 Asset×Fiat 组合。
  • 不同国家可配置不同 fiat、asset、payment_method、provider。
  • 金额输入必须同时满足 CoinW 产品限额、Provider 限额、支付方式限额和 KYC tier 限额。

Recommended 规则

首期建议按“可用 > 用户摩擦 > 成功率 > 成本 > 到账速度”排序。若无法计算综合评分，默认 Card 为 Recommended；Wallet Pay 可在设备支持时前置。

价格显示

  • 配置页显示 Estimate，不承诺锁价。
  • 真正 Quote 必须包含 provider_quote_id、expires_at、effective_price、fee、receive_amount。
  • Quote 过期后必须自动刷新，禁止使用过期价格提交。

08. CoinW Connect 架构与 Provider 抽象

产品定义：CoinW Connect 不是单一 PSP，而是 CoinW 自己的 Payment / On-ramp Experience Layer + Routing Layer。
层级职责
CoinW UX资产/法币选择、Payment Method、认证入口、报价、订单、结果页、客服。
CoinW RouterEligibility、Provider 选择、Quote 聚合、失败切换、限额、成本与成功率策略。
Provider ConnectorPSP / On-ramp API、SDK、KYC Reliance、Webhook、Settlement。
Ledger / Asset订单关联 UID、资产入账、对账、异常补单。

Provider 接入最低要求

  • 优先 Full API / Headless / Embedded SDK，可隐藏第三方品牌。
  • 支持 Quote、Order、Status、Webhook；Card 场景支持 3DS / Tokenization。
  • 优先支持 KYC Reliance / Identity Sharing；若必须二次 KYC，前端明确 Extra KYC。
  • 候选可包括：Banxa Native、OSL Pay OpenAPI、Transak Whitelabel、Nuvei、Checkout.com + Crypto Provider 等，最终以商务/牌照/覆盖确认结果为准。
前台默认不以 Provider 品牌作为一级选择；若法律披露或 Third Party 跳转要求展示，再作为二级信息露出。

09. 登录、注册与 KYC

状态Buy Now 后动作
未登录弹出 Sign up / Log in；支持 Email/Phone、Google、Apple、Telegram。
已登录未 KYC进入 CoinW KYC；成功后恢复订单上下文。
KYC Processing禁止支付；显示审核中和可返回入口。
KYC Passed请求 Provider Eligibility / Quote。
Provider 需要补充 KYC标记 Extra KYC；仅收集缺失字段，避免完整重做。

10. Payment Method 与 Quote

支付方式展示

  • Debit/Credit Card：Visa、Mastercard。
  • Apple Pay：独立一行，仅设备/地区/Provider 支持时展示。
  • Google Pay：独立一行，仅设备/地区/Provider 支持时展示。
  • Bank Transfer：P1；按地区展示 local rail / virtual account。
  • Third Party：仅在 CoinW Connect 原生能力不可用或价格显著更优时作为补充。

Quote 列表

认证后可展示多个可执行报价。每张卡只保留 Provider / Receive / Effective Price / Fee / ETA / Best 标识，避免重复信息。

12. 异常与边界场景

  • Quote 过期：自动刷新；价格变化超过阈值需用户二次确认。
  • Provider 不可用：Router 尝试下一通道；不得直接报系统错误。
  • 3DS 失败：保留订单，允许 Retry 或更换支付方式。
  • 支付成功但资产未到账：订单进入 CRYPTO_PROCESSING，禁止重复扣款。
  • 用户切换 fiat / asset 后：旧 Quote 立即失效。
  • 地区受限：在 Payment Method 层隐藏不可用选项；若全不可用，给替代方案。
  • 移动端返回：保留表单与状态，不清空。

13. 风控与合规要求

  • Provider Eligibility 必须结合用户实体、居住国、IP、KYC level、支付工具国家。
  • Card：3DS、AVS/CVV（若适用）、velocity、device/fraud signals。
  • 制裁/PEP/高风险地区沿用 CoinW 账户层规则；Provider 的额外要求由 Router 统一映射。
  • 支付工具持有人与 KYC 姓名不一致策略需合规确认。
  • 订单、Provider decision、Webhook 原文、人工操作均需 Audit Log。
  • 涉及 Provider / legal counterparty 的强制披露由法务提供统一模板。

15. SEO / Growth 预留

  • 页面 SSR / 可抓取，不依赖登录才展示核心文本。
  • 动态 Title / H1 / Meta：Buy {Asset} with {Fiat} | CoinW。
  • Programmatic Landing：/buy/btc/usd、/buy/usdt/eur 等。
  • 正文模块：How to Buy、Supported Payment Methods、FAQ、Fees、Limits、Market-specific copy。
  • FAQ Schema / Breadcrumb Schema / canonical / hreflang。

16. 技术与 API 需求

API用途建议 SLA

POST /buy/quotes并发向可用 Provider 报价P95 < 2s

关键技术要求

  • Quote 聚合并发执行，不串行等待多个 Provider。
  • 所有 create / webhook 必须幂等。
  • 前端不得持有 Provider secret；敏感支付字段使用 PCI 合规 Hosted Fields / SDK。
  • Popular 行情使用 1 次 batch API + 15~60s cache。

17. 后台 / 运营配置

  • Market Config：Country → Fiat → Asset → Payment Method → Provider。
  • Provider 开关、优先级、成本、限额、Maintenance、Fallback。
  • Recommended 规则权重配置。
  • 订单搜索：UID、CoinW Order ID、Provider Order ID、Payment Method、状态、失败原因。
  • 手动 Refresh Status / Retry Webhook / Export。
  • 运营内容：SEO 模块、FAQ、How to Buy 文案可配置。

18. 多语言与本地化

  • 资产 Symbol 与 Fiat code 固定英文；描述文本本地化。
  • 金额、千分位、小数精度按语言/法币规范处理。
  • Supported Payment Methods 按地区动态，而不是全球统一硬编码。
  • SEO landing 使用 hreflang 和本地法币关键词。
  • 移动端一行 Supported 支付方式允许横滑，不换成两行。

19. 验收标准

  1. USD 切 EUR 后，H1、金额币种、estimate、Quote price 全部同步更新。
  2. USDT 切 BTC 后，H1、Receive Asset、Popular 高亮、Quote 全部同步。
  3. Buy Now 未登录必拉起注册/登录；成功后回到原订单上下文。
  4. Payment Modal 中 Apple Pay / Google Pay 独立；Card 只包含 Visa/Mastercard。
  5. Recommended 只允许一个默认选项，且与 Router 结果一致。
  6. Quote 过期不可提交；刷新后用户可继续。
  7. 同一订单重复点击不得重复创建 Provider Order / 重复扣款。
  8. Desktop / Mobile 核心流程都可完整走通。
  9. Popular 5 个资产只使用一次批量行情请求。
  10. SEO 模块在未登录状态可抓取。

21. 待确认项 / Dependencies

  • 首发国家与法币优先级：USD / EUR / GBP / AED 的具体 rollout。
  • 首家 CoinW Connect Provider 及 fallback Provider 商务选择。
  • KYC Reliance 的法律/合规可接受范围、字段映射、用户 consent。
  • CoinW 与 Provider 谁是法币/加密服务 legal counterparty，需要如何披露。
  • Card chargeback / refund / dispute 的客服与资金责任归属。
  • Quote 是否将 CoinW markup / fee 合并展示，或拆分 fee。
  • Sell MVP 是否与 Buy 同期，还是 P1。
  • 后台 Router 是自建还是先用 Provider/Orchestration 方案。
建议决策顺序：先锁定首发市场 → 确认 Provider 白标/KYC/覆盖 → 冻结 P0 Payment Methods → 冻结 Quote/Order API → 联调 → 灰度。
